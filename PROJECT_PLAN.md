# Olly - Rust TUI Client for Ollama

*A WhatsApp-like CLI interface for coding with any Ollama model (local or cloud)*

---

## Overview

Olly is a terminal-based user interface (TUI) application built in Rust that provides an enhanced, interactive experience for using Ollama's AI models. It features workspace management, conversation history, model presets, and file context support—all wrapped in a clean, modern TUI reminiscent of WhatsApp.

**Key Benefits:**
- Use any Ollama model (including cloud models like `minimax-m2.7:cloud`, `devstral-2:123b-cloud`)
- Organized workspaces for different projects
- Persistent conversation history with search
- File/directory context inclusion
- Beautiful, responsive terminal UI

## Tech Stack

| Component | Technology | Rationale |
|-----------|------------|-----------|
| Language | **Rust** | Performance, safety, excellent CLI ecosystem |
| TUI Framework | **Ratatui** | Most actively maintained, widget ecosystem, great docs |
| Async Runtime | **Tokio** | Industry standard, works well with reqwest |
| HTTP Client | **Reqwest** | Async, streaming support, simple API |
| CLI Parser | **Clap** | Mature, feature-rich, subcommand support |
| Database | **SQLite** (rusqlite) | Embedded, zero-config, perfect for local storage |
| Config | **Figment** + **serde** | Layered configuration (defaults, file, env) |
| Prompts | **Dialoguer** | User-friendly interactive prompts |
| Markdown (optional) | **comrak** or **pulldown-cmark** | Render code blocks in chat |
| File I/O | **notify** (optional) | Watch files for context changes |

## Core Features

### 1. Workspaces

A workspace represents a project context. Each workspace stores:
- **Name**: User-defined (e.g., "Olly Development", "Personal Projects")
- **Context Paths**: Files/directories to include as context (scanned and sent as part of prompt)
- **System Prompt**: Custom system message for the model
- **Model Preset**: Default model + options (temperature, top_p, etc.)
- **History**: All conversations associated with this workspace

**SQLite Schema:**
```sql
CREATE TABLE workspaces (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    context_paths TEXT, -- JSON array of paths
    system_prompt TEXT,
    model_preset_id INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (model_preset_id) REFERENCES presets(id)
);

CREATE TABLE presets (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    model TEXT NOT NULL,
    options TEXT, -- JSON: {"temperature": 0.7, "top_p": 0.9, ...}
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE conversations (
    id INTEGER PRIMARY KEY,
    workspace_id INTEGER NOT NULL,
    title TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE CASCADE
);

CREATE TABLE messages (
    id INTEGER PRIMARY KEY,
    conversation_id INTEGER NOT NULL,
    role TEXT NOT NULL, -- "system", "user", "assistant", "tool"
    content TEXT NOT NULL,
    images TEXT, -- JSON array of base64 images
    tool_calls TEXT, -- JSON array
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);

-- Full-text search for message content
CREATE VIRTUAL TABLE messages_fts USING fts5(
    content,
    role,
    conversation_id,
    content=message
);
CREATE TRIGGER messages_ai AFTER INSERT ON messages BEGIN
    INSERT INTO messages_fts(rowid, content, role, conversation_id)
    VALUES (new.id, new.content, new.role, new.conversation_id);
END;
```

**File Context Management:**
- When a file is added to workspace context, read and hash its contents
- Store file metadata (path, hash, last_modified) in a separate table
- On each user message, include context files (either in system prompt or as separate user message)
- Watch for file changes using `notify` crate; prompt user to reload context if changed

### 2. Chat Interface (WhatsApp-like)

**Layout:**
```
┌─────────────────────────────────────────────────────────────┐
│  [Workspaces]  [Models]  [Presets]  [Search]  [?] Help    │
├─────────────────────┬───────────────────────────────────────┤
│                     │                                       │
│  My Projects        │  You: How do I create a Rust async    │
│  ─────────────      │  function?                            │
│  💼 Olly Dev        │                                       │
│  📁 Web App         │  Assistant: To create an async        │
│  📁 CLI Tool        │  function in Rust, you need to:       │
│  📁 Game            │                                       │
│                     │  1. Use `async fn` keyword           │
│  ⚙️ Settings        │  2. Return `impl Future` or use      │
│                     │     `tokio::spawn`                    │
│                     │  3. Add `#[tokio::main]` attribute    │
│                     │                                       │
│                     │  Here's an example: ...              │
│                     │                                       │
│                     │  You: Can you show me a complete     │
│                     │  example?                             │
│                     │                                       │
│                     │  Assistant: Sure! Here's a complete  │
│                     │  working example with error          │
│                     │  handling...                         │
│                     │                                       │
├─────────────────────┴───────────────────────────────────────┤
│  msg: Type your message... (Ctrl+Enter to send)            │
└─────────────────────────────────────────────────────────────┘
```

**Key Bindings:**
- `Ctrl+N`: New workspace
- `Ctrl+O`: Add file to context
- `Ctrl+S`: Search history
- `Ctrl+P`: Switch model/preset
- `Ctrl+R`: Reload context (if files changed)
- `Ctrl+Q`: Quit
- `Enter`: Send message (if single line), newline (if multi-line mode)
- `Esc`: Cancel current operation / close dialog
- `↑/↓`: Scroll history
- `PgUp/PgDn`: Page scroll
- `Tab`: Switch focus (workspace list ↔ chat)

**Chat Bubbles:**
- **User**: Right-aligned WhatsApp blue/green background
- **Assistant**: Left-aligned gray/light background
- **System**: Small, centered, dimmed
- **Tool**: Special icon/color for tool calls

**Streaming:**
- As tokens arrive, append to current message bubble
- Typewriter effect (each token appears immediately)
- Status bar shows "Receiving..." with cancel option (Ctrl+C)

**Markdown Support (Optional but Nice):**
- Code blocks with syntax highlighting (using `syntect` or `highlight` crate)
- Inline code formatting
- Lists, bold, italics
- Render in assistant bubbles only (user messages plain text)

### 3. Model Management

**List Models:**
- Poll `GET /api/tags` on startup
- Cache results locally (with TTL)
- Display in a scrollable list with tags:
  ```
  devstral-2:123b-cloud  [cloud]  75GB  256K
  devstral-2:latest      [local]  75GB  256K
  minimax-m2.7:cloud     [cloud]  -     200K
  llama3.2:latest        [local]  3.8GB  8K
  ```

**Model Presets:**
- Save custom configurations per model:
  ```toml
  [preset.coder]
  model = "devstral-2:123b-cloud"
  temperature = 0.3
  top_p = 0.9
  system = "You are an expert Rust programmer..."
  ```
- Quick-switch between presets from the UI
- Default presets for common tasks: "Coding", "Creative", "Precise", "Fast"

### 4. History & Search

- All conversations stored in SQLite
- Full-text search across messages using FTS5
- Search results show: workspace → conversation → message preview
- Jump to specific message in history
- Export conversations to Markdown, JSON, or plain text

**Search UI:**
- Press `Ctrl+S` → search input appears
- Type query → results update live
- `Enter` on result → jump to that conversation
- `Esc` → cancel search

## API Integration Details

### Ollama Chat Endpoint

**Endpoint:** `POST /api/chat`

**Request:**
```json
{
  "model": "devstral-2:123b-cloud",
  "messages": [
    {"role": "system", "content": "You are an assistant..."},
    {"role": "user", "content": "Hello!"}
  ],
  "stream": true,
  "options": {
    "temperature": 0.7,
    "top_p": 0.9,
    "num_ctx": 8192
  }
}
```

**Streaming Response (NDJSON):**
```json
{"model":"...","created_at":"...","message":{"role":"assistant","content":"Hello"},"done":false}
{"model":"...","created_at":"...","message":{...},"done":false}
...
{"model":"...","done":true,"total_duration":...,"load_duration":...,"prompt_eval_count":...,"eval_count":...}
```

**Implementation:**
- Use `reqwest::Client` with `stream()` API
- Parse each line as JSON
- Accumulate `message.content` into a `String`
- Update UI on each token (or batch for performance)
- Store full messages to DB after completion

**Error Handling:**
- Connection error → show toast, retry with exponential backoff
- Model not found → suggest available models
- Timeout → allow cancel, increase timeout for larger models
- Malformed response → log error, continue

### Model List

**Endpoint:** `GET /api/tags`

**Response:**
```json
{
  "models": [
    {
      "name": "devstral-2:123b-cloud",
      "modified_at": "...",
      "size": 0
    },
    ...
  ]
}
```

**Implementation:**
- Cache in memory with timestamp
- Refresh on user request (`Ctrl+R`)
- Parse tags: `model:tag` format

## Challenges & Solutions

### 1. Streaming + TUI Flicker

**Problem:** Frequent redraws during streaming can cause flicker in some terminals.

**Solution:**
- Use Ratatui's `Terminal::draw` with minimal updates
- Only redraw when new content arrives (not on every token, maybe batch 10ms)
- Double buffering is built into Ratatui
- Consider `crossterm` backend for better performance

### 2. Large Context Windows

**Problem:** Cloud models like Devstral 2 have 256K context. Including many large files can exceed limits or cause performance issues.

**Solution:**
- Implement `context_strategy`:
  - `files`: Read full file contents (for small files)
  - `summary`: Store file summaries instead of full contents (for large files)
  - `directory_tree`: Only include file tree structure, not contents
- Automatic truncation with warning if context too large
- Allow user to manually exclude files

### 3. File Watching

**Problem:** User edits files while they're in workspace context. How to detect changes?

**Solution:**
- Use `notify` crate to watch all context paths
- On change event: show toast "Context files modified. Press Ctrl+R to reload."
- Store file checksums; only mark as changed if hash differs
- Don't auto-reload (might be in middle of conversation)

### 4. Image Support

**Problem:** Multimodal models accept images (base64). How to include in chat?

**Solution:**
- Allow image attachments via file picker (terminal-based)
- Limit size (resize/compress if needed)
- Store as base64 in message (increases DB size)
- UI: show thumbnail in chat bubble

### 5. Cloud Model Availability

**Problem:** Cloud models might require authentication or have downtime.

**Solution:**
- No special handling needed—Ollama daemon manages it
- Show "cloud" tag in model list for clarity
- If API call fails with 402 (payment required) or model-specific error, show appropriate message
- Retry logic with exponential backoff
